## 1. 当前视觉状态评估

### 1.1 现状总结

项目当前处于**纯代码绘制阶段**——所有视觉元素由 `_draw()` 调用和代码生成 UI 构成，零图片资源、零精灵、零粒子、零 Shader。

| 模块 | 当前实现 | 视觉层级 |
|------|----------|----------|
| 棋盘格 | `draw_rect` 交替色块 + 2px 线框 | 原型级 |
| 地形格 | 颜色填充 + 文字标签（HIGH/TRAP/遭遇/回复/商店/宝箱） | 原型级 |
| 单位 | 46x46 纯色矩形（青=玩家，红=敌方）+ 2字缩写名 | 原型级 |
| 高亮 | 半透明矩形覆盖（青/红/紫） | 原型级 |
| 攻击反馈 | 白色闪烁 + 浮动伤害数字 | 基础级 |
| 棋盘背景 | 全屏暗色 ColorRect | 原型级 |
| 卡牌战斗面板 | CyberStyle 面板 + 文字按钮 | 基础级 |
| 奖励/升级面板 | CyberStyle 面板 + 文字按钮 | 基础级 |
| 牌组面板 | RichTextLabel 列表 | 基础级 |
| HUD | 纯标签 + CyberStyle 按钮 | 基础级 |
| 掷骰演出 | 无（直接更新数字） | 缺失 |
| 召唤演出 | 无（直接出现） | 缺失 |
| BGM/音效 | 无 | 缺失 |

### 1.2 已有优势

- **CyberStyle 体系完善**：统一的赛博朋克配色（17种颜色常量）、面板工厂、按钮工厂已就绪，新增视觉只需在此基础上扩展
- **Tween 动画基础**：已有浮动数字、闪烁反馈的 Tween 模式，可复用
- **架构清晰**：渲染（BoardView）和逻辑（BFC）分离，美化不影响游戏逻辑

### 1.3 约束条件

- **渲染器**: `gl_compatibility`（不支持 Vulkan-only Shader 特性，但支持 CanvasItem Shader）
- **引擎**: Godot 4.6.1（支持 CPUParticles2D、CanvasItem Shader、Tween、AnimationPlayer）
- **布局**: 全部绝对像素定位（1280x720 设计分辨率）
- **BoardView 已 648 行**：禁止继续堆积渲染逻辑，需剥离新增视觉到独立模块

## 3. 分阶段推进计划

### Phase 1：格子与单位视觉升级（P0 — 最高优先）

**目标**：棋盘从"调试原型"变为"有风格辨识度的游戏画面"

**子任务 1.1 — 棋盘格视觉升级**

将 `_draw_board()` 从纯色块升级为赛博朋克风格格子：

```
当前：纯色交替矩形 + 细线框
目标：
  - 格子内部渐变填充（中心暗→边缘微亮）
  - 发光边缘线（用 draw_line 叠加亮色半透明线条模拟辉光）
  - 不同格子类型使用独特图标符号（替代纯文字标签）
    - HIGH → ▲ 三角图标 + 金色发光
    - TRAP → ✖ 十字图标 + 红色脉冲
    - 遭遇 → ⚡ 闪电图标 + 橙色呼吸
    - BOSS → 💀 骷髅图标 + 深红脉冲 + 粗发光框
    - 回复 → ✚ 十字图标 + 蓝白发光
    - 商店 → ◆ 菱形图标 + 青绿发光
    - 宝箱 → ⬡ 六角图标 + 金色发光
    - 事件 → ? 保持但加大+发光
  - 格子坐标微标注（角落半透明小字，调试用可选）
```

**技术方案**：
- 新建 `Scripts/UI/BoardCellRenderer.gd`（class_name 注册）
- 提供 `static func draw_cell(canvas: CanvasItem, pos: Vector2, size: Vector2, cell_type: String, time: float)` 系列方法
- BoardView._draw() 中调用 BoardCellRenderer 的静态方法替代现有 draw_rect
- 呼吸/脉冲效果通过 `Time.get_ticks_msec()` 驱动 sin() 周期变化实现，无需 Tween

**子任务 1.2 — 单位视觉升级**

将单位从纯色矩形升级为可辨识的角色表现：

```
当前：46x46 纯色矩形 + 2字名称缩写 + HP文字
目标：
  - 玩家单位：圆角矩形 + 发光轮廓 + 单位类型独特图标
    - 刀盾犬 → 盾形图标（■+边框发光）
    - 黑客狐 → 菱形图标（◆+边框发光）
    - 鸦术士 → 三角图标（▼+边框发光）
  - 敌方单位：暗红底 + 锯齿边框暗示威胁
  - HP 条（替代纯数字）：格子下方薄条，绿→黄→红渐变
  - 选中状态：金色脉冲边框（替代静态金色线框）
  - idle 微动画：选中单位轻微上下浮动（1-2px，sin波）
```

**技术方案**：
- 新建 `Scripts/UI/UnitRenderer.gd`（class_name 注册）
- 提供 `static func draw_unit(canvas, pos, unit_data, is_selected, time)` 等方法
- HP 条用 `draw_rect` 双层（底色+当前HP比例填充）
- 选中脉冲用 `sin(time * 3.0) * 0.15 + 0.85` 控制 alpha
- idle 浮动用 `sin(time * 2.0) * 2.0` 控制 y offset

**子任务 1.3 — 高亮系统升级**

```
当前：半透明矩形覆盖
目标：
  - 移动高亮：青色角标（四角 L 形线条）+ 内部微弱扫描线
  - 攻击高亮：红色十字准星 + 脉冲边框
  - 召唤高亮：紫色圆环标记
```

**预估规模**：~200行 BoardCellRenderer + ~150行 UnitRenderer + ~80行 BoardView 修改
**风险**：BoardView 修改量需控制，核心是用新 Renderer 替换旧 draw 调用，不新增逻辑

### Phase 2：动态演出系统（P1）

**目标**：关键操作有"感觉"——掷骰有期待感、攻击有冲击感

**子任务 2.1 — 掷骰演出**

```
当前：点击掷骰 → crest 数字直接更新
目标：
  - 掷骰按钮按下后：
    1. 骰子区域显示旋转/翻滚动画（2D 骰面序列帧或程序化旋转方块）
    2. 落定后 crest 图标逐个弹出（scale 0→1.2→1.0 + 发光闪烁）
    3. 6种 crest 用独特颜色+图标区分
  - 持续时间：~1.2秒（可调）
```

**技术方案**：
- 新建 `Scripts/UI/DiceRollAnimation.gd`
- 在 DiceDebugPanel 中嵌入，掷骰时播放
- 使用 Tween 链实现序列动画
- 6种 crest 图标用 `draw_*` 程序化绘制（避免依赖图片资源）

**子任务 2.2 — 攻击演出增强**

```
当前：白色闪烁 + 浮动数字
目标：
  - 攻击命中：
    1. 屏幕微震（BoardView 整体 position 偏移 2-4px，快速回弹）
    2. 命中格粒子爆裂（CPUParticles2D，5-8个小方块四散）
    3. 伤害数字弹出增强（先放大后缩小+颜色渐变）
  - 击杀时：更大粒子爆裂 + 闪光持续更久
  - 敌方攻击预警：目标格红色脉冲 + 方向箭头指示
```

**技术方案**：
- 新建 `Scripts/UI/BattleEffects.gd`（管理粒子和屏幕效果）
- 屏幕震动：Tween 控制 BoardView.position
- 粒子：CPUParticles2D（gl_compatibility 兼容，不依赖 GPU 粒子）
- 粒子节点动态创建+自动释放

**预估规模**：~120行 DiceRollAnimation + ~160行 BattleEffects + ~50行接入修改
**风险**：低，纯添加式，不修改现有逻辑

## 5. 架构约束与技术规范

### 5.1 新增文件规划

| 文件 | 职责 | 预估行数 |
|------|------|----------|
| `Scripts/UI/BoardCellRenderer.gd` | 格子渲染（class_name 注册，静态方法） | ~200 |
| `Scripts/UI/UnitRenderer.gd` | 单位渲染（class_name 注册，静态方法） | ~150 |
| `Scripts/UI/BattleEffects.gd` | 战斗特效（粒子/震屏/命中效果） | ~160 |
| `Scripts/UI/DiceRollAnimation.gd` | 掷骰动画控件 | ~120 |
| `Scripts/UI/CardRenderer.gd` | 卡牌样式渲染（可选，Phase 3） | ~200 |
| `Scripts/System/AudioManager.gd` | 音效管理器（Phase 5） | ~100 |

### 5.2 硬规则

- **不修改 BoardView 的逻辑代码**（点击处理、信号等），仅替换 `_draw` 中的渲染调用
- **新 Renderer 全部用 class_name 注册 + 静态方法**，与 CyberStyle 同模式
- **所有颜色必须走 CyberStyle 常量**（如需新增颜色，先扩展 CyberStyle）
- **CPUParticles2D 替代 GPUParticles2D**（gl_compatibility 兼容性）
- **动画时长需可配置**（常量定义在 Renderer 顶部）
- **Phase 1-4 不依赖外部图片资源**（全部程序化绘制，保持零依赖的纯净度）
- **Phase 5 音效可用外部资源**，放 `Project/Audio/` 目录

### 5.3 瘦身策略

Phase 1 完成后，BoardView 应从 648 行下降（旧 draw 方法删除，被 Renderer 静态调用替代）。目标是 BoardView 回到 500 行以下。

## 7. 风险与注意事项

1. **BoardView 行数控制**：每次修改必须统计行数，超过 700 行必须先剥离
2. **性能**：CPUParticles2D 不要超过 3 个同时活跃实例；`_draw()` 中避免每帧创建新对象
3. **gl_compatibility Shader 限制**：CanvasItem Shader 可用但功能受限，复杂后处理（如 bloom）不可用
4. **呼吸/脉冲动画**：统一使用 `Time.get_ticks_msec()` 驱动，不要为每个格子创建独立 Tween
5. **Phase 6 (2.5D) 需要 Codex 复审**：涉及坐标系变更和 BoardView 大幅重写，执行前需确认方案
