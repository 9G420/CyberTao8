# CyberTao: Dice Beast Protocol
## 2.5D Demo 新预期方案报告（中文）

**生成时间**: 2026-03-29  
**适用阶段**: 当前“最小可玩战斗 demo 原型”之后  
**目标**: 从可玩原型推进到“美观、好玩、有沉浸感、可给他人试玩”的 2.5D Demo

---

## 1. 当前阶段判断

当前项目已经完成了最小可玩战斗 demo 的基础闭环，具备：

- 掷骰
- 移动
- 攻击
- 敌方最小回合
- 胜负判定
- 重开
- 显示设置

这说明项目已经脱离“纯脚手架”和“纯概念验证”阶段，进入：

**“可以继续打磨成正式 Demo 的原型期”**

但当前版本仍然存在明显不足：

- 棋盘表现仍偏平面调试风格
- 玩法特色还没有完全体现
- summon / path-building 还没真正落地
- buff / item 棋盘互动还不够
- 骰子决斗的“仪式感”和“沉浸感”还不足

---

## 2. 总体目标

目标不是直接做成最终商业版，而是先做出一个：

**“能让玩家觉得酷、能玩出味道、愿意继续试下去”的 2.5D Demo。**

这个 Demo 应具备：

1. 明确的核心玩法辨识度
2. 足够顺手的战斗闭环
3. 明显优于纯平面原型的视觉表现
4. 适合录视频、给他人试玩、继续募反馈

---

## 3. 推荐开发路线

### 第一阶段：玩法特色落地
**目标：让项目不再只是普通战棋原型**

预计周期：**1~2 周**

必须完成：

1. `summon / path-building` 第一版
2. buff / item 格第一版
3. 敌方 AI 再稳定一点
4. 调试面板逐步弱化，战斗信息更游戏化

阶段完成标准：

- 召唤不只是“凭空出单位”，而是开始和路径展开绑定
- 棋盘不只是走位和攻击，还存在额外互动点
- 玩家能感受到这不是普通战棋，而是“骰兽协议”

---

### 第二阶段：最小完整战斗 Demo
**目标：形成一个能连续玩几局的小 demo**

预计周期：**1~2 周**

必须完成：

1. 战斗开局更明确
2. 胜利 / 失败后的流程更顺
3. 至少 3~5 个可用单位
4. 至少 2~3 个 summon / path 变化
5. 至少 2~3 个棋盘 buff / item
6. 数值初步可玩，不至于太卡手

阶段完成标准：

- 一局从开始到结束都顺畅
- 玩家能理解规则
- 不再只是单步测试器，而是一个可重复游玩的战斗 demo

---

### 第三阶段：2.5D / 伪3D 战场升级
**目标：从“能玩”变成“看起来有味道”**

预计周期：**1~3 周**

建议重点：

1. 棋盘整体改为倾斜透视风格
2. 格子带厚度、发光边缘、悬浮感
3. 单位从纯平块升级为：
   - 立板式角色
   - 或伪 3D 精灵
4. 路径格和普通格明显区分
5. 背景升级为“赛博道境战场”

阶段完成标准：

- 视觉上摆脱调试工具感
- 玩家一眼能看出这是一个有风格的战斗场景
- 即使玩法未全量完成，也已经具备展示价值

---

### 第四阶段：仪式感演出
**目标：做出“游戏王DM骰子决斗”那种沉浸感**

预计周期：**1~2 周**

建议优先级：

1. 骰子投掷演出
2. summon 演出
3. 路径展开演出
4. 攻击命中特效增强
5. 镜头感 / 局部震动 / 屏幕反馈

这一阶段最优先的不是单位细节，而是：

**骰子投掷演出**

因为它最能快速提升项目辨识度和“仪式感”。

---

### 第五阶段：Demo 包装
**目标：能拿给别人试玩并留下印象**

预计周期：**数天到 1 周**

建议补齐：

1. 主菜单更像正式游戏
2. 教学提示更清楚
3. 设置菜单更完整
4. UI 风格统一
5. 战斗结束反馈更完整
6. Demo 的首轮体验更流畅

阶段完成标准：

- 别人第一次打开就知道怎么玩
- 试玩一小段后能记住这个项目
- 适合录视频、截图展示、给外部试玩

---

## 4. 时间预估

基于当前推进速度，较现实的估计如下：

### 可玩战斗 Demo

预计：**1~3 周**

条件：

- `summon / path-building` 第一版落地
- buff / item 格接入
- AI 稳定
- 反馈继续增强

### 美观的 2.5D Demo

预计：**4~8 周**

条件：

- 棋盘 2.5D 化
- 骰子演出
- 召唤演出
- UI 与战场风格统一

### 更适合展示的高完成度 Demo

预计：**6~10 周**

条件：

- 战斗与视觉双线都明显成熟
- 演出足够稳定
- 试玩流程更完整

---

## 5. 推荐视觉路线

不建议直接把整个项目完全重做成重 3D。

最优路线是：

**2D 逻辑 + 2.5D 棋盘 + 伪 3D 单位 + 骰子演出**

原因：

1. 成本更可控
2. 与当前项目基础更兼容
3. 更容易快速做出“看起来很酷”的效果
4. 不会一下把开发复杂度炸开

---

## 6. 当前最关键的策略

接下来最重要的不是“立刻变美”，而是：

**先把玩法特色做出来，再做视觉放大。**

正确顺序应该是：

1. `summon / path-building`
2. `buff / item`
3. `2.5D 棋盘`
4. `骰子演出`

不要反过来。

如果先花很多时间做纯视觉，而玩法辨识度还没落地，Demo 会变成“看起来有点酷，但玩起来没特色”的半成品。

---

在 Codex 额度紧张阶段，Mulerun 后续适合按下面顺序推进：

5. 棋盘 2.5D 第一版
